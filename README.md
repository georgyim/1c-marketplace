# FBS Marketplace Connector

Пет-проект на 1С:Предприятие 8.5 (разработка в 1C:EDT) с внешним mock-сервисом на Node.js.

Моделирует работу компании, которая торгует на маркетплейсах (Ozon, WB) по схеме FBS: товары закупаются у поставщиков и лежат на своем складе, 1С ведет учет и выгружает свободные остатки с ценами наружу, а сервис маркетплейса присылает новые заказы и смены статусов по HTTP.

## Стек

- 1С:Предприятие 8.5, 1C:EDT, СКД, управляемые формы, HTTP-сервисы
- Node.js, SQLite (mock API маркетплейса)

## Что сделано в 1С

**Склад и партии**
- Поступление товаров от поставщиков оформляется документом «Приходная накладная».
- Физический остаток ведется по партиям (партия = документ поступления), резервы под заказы — отдельно.
- Доступный остаток для выгрузки считается как `Физ. остаток - В резерве`.
- При проведении стоит контроль: нельзя зарезервировать больше доступного и нельзя списать в минус по партиям.

**Цены и комиссии**
- Документ «Установка цен маркетплейса» записывает отпускную цену и % комиссии в периодический регистр сведений.
- При создании заказа актуальные значения подтягиваются на дату документа через `СрезПоследних`.

**Заказы FBS и взаиморасчеты**
Работа с заказом идет в одном документе «Заказ маркетплейса» со сменой статусов:
1. `ОжидаетСборки` — товар ставится в резерв, партии и взаиморасчеты не меняются.
2. `Доставлен` — резерв снимается, партии списываются по ФИФО, фиксируются выручка, комиссия и себестоимость, начисляется долг маркетплейса (`Сумма заказа - Комиссия`).
3. `Отменен` — резерв снимается, товар возвращается в свободный сток.

**Отчет**
- Отчет на СКД «Доступные остатки (Свободный сток)»: на выбранную дату показывает физический остаток, резерв, сколько доступно к продаже, минимальный остаток и флаг дозаказа.

## Интеграция (1С <-> Node.js)

Входящие запросы в 1С (`/hs/market`):
- `POST /hs/market/orders` — принимает JSON (`orderId`, `marketplaceInn`, `items: [{ sku, qty }]`). Ищет товары по индексированному артикулу, берет цену и комиссию на дату заказа, проверяет остаток и проводит документ в статусе `ОжидаетСборки`. При нехватке стока возвращает `400 Bad Request`.
- `PATCH /hs/market/orders/{orderId}/status` — принимает `delivered` или `cancelled`, ищет заказ по индексированному `НомерЗаказаМП`, меняет статус и перепроводит документ.

Исходящий запрос из 1С (`HTTPСоединение`):
- `POST http://localhost:3000/api/stocks` — отправляет в Node.js текущие свободные остатки и действующие цены по `sku`.
